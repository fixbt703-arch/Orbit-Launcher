# Orbit Connect — состояние поставки 1.5.4

Orbit Connect открывает LAN-мир Minecraft через интернет без аренды игрового
сервера. Сетевые приложения запускаются отдельно от JVM; Orbit Client не требуется.
Это встроенная интеграция Orbit Launcher, а не самостоятельный универсальный mod JAR.

Сборка 1.5.4 заменяет прежний `dist/OrbitLauncher.exe`. Проверен запуск именно
опубликованного single-file EXE: фоновый контроллер работает без окна, принимает
аутентифицированный локальный запрос и завершается вместе с прикреплённой игрой,
удаляя свои временные управляющие файлы.

## Как играть

1. У обоих игроков включите **Orbit Connect** под Orbit Client при создании сборки
   или в её параметрах. Запустите Minecraft заново. Переключатель независим от
   Vanilla, Fabric, Forge, NeoForge и Quilt.
2. Используйте совместимые версии Minecraft и одинаковые обязательные моды.
3. Хозяин входит в мир и выбирает штатное **Открыть для сети**. Адаптер получает
   фактически открытый порт; готовое приглашение появляется в панели Connect.
   В проверенном Minecraft 26.2 оно также появляется в чате: откройте чат и нажмите
   **Скопировать приглашение**. Текст приглашения не печатается в игровой журнал.
4. Гость вставляет `orbit1:…` в обычное **Прямое подключение** — проверено на 26.2.
   Для остальных интерфейсов: ПКМ по сборке → **Orbit Connect** → вставить код →
   **Подключиться**, затем выбрать Orbit Connect в списке LAN-миров Minecraft.
   Панель также позволяет скопировать локальный адрес. Для старых клиентов с
   автономным профилем выбирайте именно LAN-запись: обычный серверный адрес может
   требовать серверную аутентификацию. Поддерживаются и коды `U/…` Terracotta.
5. Закрытие панели/лаунчера сохраняет подключение, пока работает игра. Закрытие
   мира отзывает приглашение; новый мир получает новый секрет.
6. **Отключить** останавливает текущую публикацию. Она не возобновляется простым
   опросом состояния; следующее открытие LAN-мирa создаёт новую публикацию.

Если автоматический игровой адаптер не распознал интерфейс версии, откройте панель
и укажите LAN-порт из чата вручную. Версии без штатного открытия мира для сети
не получают эту возможность автоматически. Игровой адаптер требует Java 8+.

При первом запуске включённой интеграции скачиваются около 41 МБ фиксированных
компонентов непосредственно с GitHub EasyTier/Terracotta. После проверки SHA-256
они кэшируются. Повреждённые файлы заменяются атомарно; установка согласована между
фоновыми процессами. Миры, аккаунты и пользовательские моды при этом не меняются.

## Маршруты и задержка

- EasyTier 2.6.4: прямой UDP P2P, штатный relay при необходимости, два независимых
  владельца bootstrap/relay. При подтверждённой потере пути может добавляться WSS.
  Исправный core не перезапускается из-за небольших изменений RTT.
- Один транспорт каждого владельца при старте, прямые слушатели только UDP;
  `latency_first=false` сохраняет приоритет прямого пути. У собственных TCP-мостов
  отключён Nagle, нет искусственной задержки/сжатия/повторной передачи игровых пакетов.
- Мониторинг раз в 2 секунды; три неудачных наблюдения до восстановления.
  Для работающего процесса последняя смена движка откладывается минимум на 60 секунд
  после добавления маршрута. Завершение core обрабатывается сразу.
- Terracotta 0.4.2 — дополнительный P2P-адаптер, подготовленный заранее, если доступен.
  До включения его кода проверяется `c:server_port` и PID игры: сканирование чужого
  LAN-мира не выдаёт пользователю чужое приглашение.
- Внутри EasyTier смена маршрута может сохранить текущий TCP-поток — проверено на
  управляемых relay. При гибели процесса/смене движка может понадобиться повторный
  вход в Minecraft. Сохраняется локальный адрес входа, а не обещание сохранения TCP.
- Показатель пинга — фактическая оценка текущего маршрута/запроса статуса мира.
  Близкие игроки получают низкую задержку при прямом P2P. При блокировке P2P пинг
  зависит от расположения и нагрузки relay; малый интернет-пинг не гарантируется.

| [Страница владельца Jiali](https://upt.jiali.yun/), us01.225284.xyz:11010 | TCP, независимый владелец | Реальная зашифрованная передача; медиана 613 мс, аварийный резерв |

Проверки публичных узлов были короткими, без нагрузочного теста. Порт, принимающий
TCP, сам по себе не считается рабочим relay. 161.33.207.13 исключён после тайм-аута
родного handshake. Штатные public.easytier.top/public2.easytier.cn не включены в
каталог Orbit после недоступности из текущей сети. Штатные узлы Terracotta не
объявляются разрешёнными relay: Terracotta использует режим P2POnly.

## Изоляция

Локальный API привязан к 127.0.0.1, требует случайный bearer-токен и отклоняет Origin,
чрезмерные/неоднозначные запросы. Перед публикацией проверяется принадлежность
LAN-порта PID игры. EasyTier работает без TUN/сетевого драйвера, с whitelist игрового
TCP-порта, без общего проксирования домашней сети. Другая сеть/секрет не достигает
мира; соседний локальный порт через основной transport недоступен — проверено.

Секреты конфигурации и временные журналы Terracotta находятся в приватных каталогах
текущего пользователя. Родные приложения неизменены, их HTTP/CLI не загружаются в JVM.
Windows job objects останавливают принадлежащие контроллеру процессы при его аварии.
Нативные зависимости не входят в распространяемый EXE, их версии/источники/digest
указаны в `assets/OrbitConnect/components.json`. Лицензии сохраняются рядом с runtime.

## Что фактически проверено

Совместимость с установленным «Запретом» 1.10.3: проверены все 22 стратегии с
текущими фильтрами; подробная матрица, повторные проверки, три настоящих игровых
запуска и ограничения — в [отчёте](ORBIT_CONNECT_ZAPRET.md). Единичные тайм-ауты
первых проходов сохранены в результатах и не выдаются за отсутствие сбоев.

| Управляемый relay-failover, 30 минут | 28 089 кадров, 460 210 176 байт без искажений; тот же TCP пережил потерю одного relay; p50 1,68 мс / p95 15,82 мс |

| UI | Состояния ожидания/публикации/входа/ошибки, RU/EN, компактное окно, действия копирования |

Пять загрузчиков доступны в настройках и не подменяются интеграцией. Полная игровая
матрица 1.7.10/1.12.2/1.16.5/1.20.1/1.21.x/26.x на всех существующих загрузчиках
**не пройдена**. Для непроверенных игровых интерфейсов предусмотрена панель лаунчера.
Для Minecraft 1.3–1.6 реализована проверка старого LAN-status протокола; проверка
байтового fixture не выдаётся за запуск каждого старого клиента.

**Не выполнено:** 60 минут игры через двух разных провайдеров, отдельная матрица
смены физического интерфейса и конкурирующих UDP/TCP-путей под реальной нагрузкой.
Нулевые вылеты/потери и универсальный минимальный пинг не заявляются.

## Воспроизведение

Используйте x64 `C:\Program Files\dotnet\dotnet.exe`.

```powershell
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release -- --connect-ui-smoke <new-output>
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release -- --connect-transport-smoke <new-output>
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release -- --connect-session-smoke <new-output>
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release -- --connect-monitor-race-smoke
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release -- --connect-published-smoke <path-to-dist-OrbitLauncher.exe>
./OrbitConnect/build.ps1
./OrbitConnect/test.ps1
./OrbitConnect/build-live-test.ps1
dotnet run --project Tests/OrbitLauncher.Tests.csproj -c Release -- --connect-game-smoke <new-isolated-folder> <path-to-connect-live-test.jar>
./build.bat
```

Игровой smoke требует уже установленных 26.2/Fabric 0.19.5 и JDK 25. Он создаёт
новые каталоги и тестовые миры, не использует аккаунты/миры пользователя и завершает
только созданные им процессы. Native smoke скачивает фиксированные компоненты, если
нет кэша. Тесты не следует собирать одновременно с работающим тестовым EXE.
