# Orbit Launcher 1.6.3 — Zapret ALT9 compatibility

## Verified failure and fix

Live tests used the local Zapret 1.10.3 / winws v72.9 with WinDivert capture confirmed. The installed ALT9 strategy passed normal checks, but its IP set contained only the documentation address `203.0.113.113/32`: most launcher hosts were not selected. This alone did not reproduce the friend's report.

A temporary, target-specific profile then applied ALT9's `hostfakesplit` parameters to launcher service hosts. All 26 probes failed with launcher 1.6.1; six probes also failed with the previous transport. A VPN TUN interface was active. TCP write splitting was insufficient in this environment. TLS-record fragmentation also failed without Zapret and was not shipped. The ineffective TCP splitting was removed in 1.6.2.

The supported correction is to exclude launcher service domains from Zapret's packet modifications. With the same active driver and temporary exclusions, all 26 probes passed for each `ts` and `ts,md5sig` variant. The final profile used the exclusion file generated by the actual repair service. Live Vanilla/Fabric instance creation and reopening, official Minecraft/Ely component downloads, CurseForge catalog pages and icons, and Minecraft 26.2/Fabric launch with the player's own Ely skin passed.

These tests were performed on this computer. The friend's exact Zapret lists, ISP and computer are still untested.

## User action

1. Install launcher 1.6.3.
2. Open **Settings → Zapret compatibility → Repair compatibility**.
3. Select the main Zapret folder containing `service.bat`, `bin` and `lists`.
4. Fully stop and restart Zapret, then retry the download, launch or skin operation.

The repair appends missing service domains to `lists/list-exclude-user.txt` inside an identified Orbit comment block. It preserves existing bytes/comments and does nothing on repeated application. Exact original/applied copies are stored outside Zapret, under `%LOCALAPPDATA%\OrbitLauncher\backups\zapret\<folder-hash>`. No backup directory is created inside Zapret.

To undo this change, choose **Settings → Zapret compatibility → Remove compatibility**, select the same Zapret folder, then fully restart Zapret. Removal preserves preexisting exclusions and later user entries. An untouched list is restored byte-for-byte; with later edits, only the proven Orbit block is removed. Intact managed comments also identify the new block if external ownership copies have been lost. Edited or malformed blocks are left untouched with a recovery message.

The remove button appears only when the selected installation contains removable Orbit compatibility records. The selected folder is remembered in launcher settings; older installations default to `Desktop\Zapret`. A read-only check runs at startup, on opening Settings and after either action. Existing backups and user-owned exclusions alone do not show the button. Inspection does not migrate files or create undo receipts.

On either action, recognized backups from older `.orbit-launcher-backups` folders are copied and verified in the external store before their old files are removed. The old directory is removed only when empty; unrelated files remain. Legacy unmarked additions are removed only when their original backup proves the exact appended range. Ambiguous edits abort without changing the list. Durable undo receipts prevent a repeated removal from consuming identical domains added later by the user.

The launcher never restarts programs, elevates itself, changes firewall rules, disables certificate validation or replays login/upload requests. Both Zapret and the external backup location must be writable. A detected concurrent editor change aborts with a retry message. Atomic replacement uses a temporary file beside the exclusion list, allowing backups on another volume.

## Scope and verification

- 20 official service parent domains cover Mojang/Minecraft, Fabric/Quilt/Forge/NeoForge, Modrinth/CurseForge, Ely.by, GitHub and Microsoft/Xbox authentication.
- Original Zapret files and configuration were left unchanged after testing. All test-owned winws processes were stopped. Tests used temporary profiles and isolated game/library/account fixtures.
- The earlier 1.6.2 live network verification is recorded above; the driver strategies are unchanged in 1.6.3. This update passes 177 launcher regression tests with Orbit Connect excluded, plus an isolated service run of 28 checks including real C:/D: backup and undo. Normal unelevated runs explicitly skip the optional file-symlink fixture when Windows privilege 1314 is unavailable.
- UI renders in Russian and English; apply and remove actions are keyboard accessible and their results stay inside the window. Backup paths are shown separately. Source export includes the partial class and tests.
- The initial GET/HEAD deadline remains four seconds so the existing TLS 1.2 fallback can start within a ten-second skin preview budget. POST requests retain twelve seconds and are not automatically replayed. GitHub downloads share the bounded launcher transport and retain HTTPS/redirect/hash validation.
- HTTP 401 from an unauthenticated Minecraft profile endpoint and HTTP 403 from the CurseForge website are transport responses, not proof of successful authentication. The configured CurseForge API was separately checked with two populated catalog pages.
- Authenticated skin upload, licensed server access, every Minecraft version/loader, and the friend's computer were not tested. A custom API/CDN domain outside the supported list may need its own Zapret exclusion. A service independently blocked by an ISP may still require the user's existing working network route.
