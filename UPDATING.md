# Автообновление Orbit Launcher

## Для пользователя

Лаунчер проверяет GitHub Releases после запуска и каждые шесть часов работы.
При новой стабильной версии появляется окно с изменениями и кнопками
«Обновить сейчас» / «Позже». После «Позже» эта версия не предлагается повторно
в текущем сеансе; её можно установить из настроек. При следующем запуске
предложение появляется снова. Ручная проверка находится в настройках.

Загрузка показывает фактический прогресс. Её можно отменить. При сетевой
ошибке или неверном файле лаунчер остаётся открыт, доступен повтор.
Установщик запускается только после проверки размера, SHA-256 и версии EXE.
После успешного запуска установщика лаунчер закрывается; установка ждёт
завершения именно этого процесса и затем снова открывает лаунчер.
Minecraft не завершается. Миры, сборки, скины и аккаунты хранятся отдельно.

## Как выпустить обновление

1. Увеличьте `<Version>` в `OrbitLauncher.csproj`, например до `1.5.0`.
2. Соберите релиз через `tools/Build-GitHub.ps1`.
3. В публичном репозитории `fixbt703-arch/Orbit-Launcher` создайте GitHub Release
   с тегом `v1.5.0` и отметьте его последним стабильным релизом (Latest).
4. Прикрепите **`release/OrbitLauncherInstaler.exe`** и **`release/SHA256SUMS.txt`**
   из созданной папки `OrbitLauncher-GitHub`.
5. Добавьте описание изменений и опубликуйте релиз.

Версия в теге должна совпадать с версией собранного установщика.
`1.5`, `1.5.0` и `1.5.0.0` сравниваются одинаково; `v` разрешён.
Для существующих текстовых тегов вроде `BigBugFix` поддерживается название
релиза строго вида `Orbit Launcher 1.5.0`. Для новых релизов используйте
числовые теги. Переименовать старый установщик или только изменить название
релиза недостаточно: несоответствие версии EXE будет отклонено.

Черновики, prerelease и версии не новее установленной не предлагаются.
Простой push исходников или создание Git-тега без GitHub Release не запускает
обновление. Приватные релизы недоступны обычным пользователям; секретный
GitHub-токен в лаунчер не встраивается. Адрес репозитория задан публичными
константами в `Utilities/AppConfiguration.cs`.

GitHub предоставляет digest загруженных файлов; если SHA-256 отсутствует в API,
лаунчер читает `SHA256SUMS.txt` из того же релиза. Произвольные внешние адреса
установщиков и перенаправления вне серверов GitHub отклоняются.

## Проверка разработчиком

Основной набор тестов включает ответы API, сравнение версий, фильтрацию релизов,
проверку ссылок и контрольных сумм, отмену и очистку неполных загрузок.
Сценарии используют временные данные и не запускают установщик.

`--update-preview <папка>` у тестового проекта рендерит настоящее WPF-окно
с явно демонстрационной версией и описанием. Сеть и установка в этом режиме
отключены.

Первую сборку с автообновлением пользователи устанавливают вручную:
в прежних EXE механизма проверки ещё нет.
